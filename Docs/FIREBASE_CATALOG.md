### MP4 URL 지원

영상 URL은 `.m3u8` 또는 `.mp4`로 끝나는 HTTPS 파일 경로를 받는다. 뒤에 쿼리 파라미터가 붙어도 된다. YouTube 재생 페이지 등 HTML URL은 받지 않는다. iOS는 MP4에 별도 진도 ID를 사용하고 실제 파일의 자막·음성 트랙을 조회한다. 기존 번들 데모의 안내 자막을 외부 MP4에 표시하지 않는다. MP4 코덱은 iOS에서 재생 가능해야 한다. HLS 변환·인코딩은 하지 않는다.

### MP4 직접 업로드 (2026-11-02)

관리자에서 작품 정보 입력 → MP4 파일 선택 → 파일 업로드 → 완료 후 저장 → 필요하면 공개 순서다. 새 작품은 파일 업로드 시 비공개 초안을 생성하며 별도 영상 URL 입력이 필요 없다. 파일당 500,000,000바이트(500MB) 이하로 제한한다. 원래 파일명은 업로드 경로에 사용하지 않으며 `videos/{titleId}/{UUID}.mp4`에 저장한다. 업로드 진행률과 취소를 제공하고 로그아웃 시 전송 취소·늦은 URL 응답 무시를 수행한다. 브라우저를 닫았다 다시 열어 이어 올리기는 지원하지 않는다.

클라이언트는 확장자·MIME·MP4 ftyp 헤더를 확인한다. 이는 전체 영상 코덱 검증이나 악성코드 검사가 아니다. 서버 규칙은 승인된 Google 관리자만 생성·SDK 조회하도록 제한하며 크기·contentType·작품/업로더 메타데이터를 확인한다. 기존 파일 덮어쓰기와 클라이언트 삭제는 금지한다. 재업로드는 새 객체를 만든다.

업로드 후 생성되는 Firebase download-token URL은 URL을 가진 사람이 재생할 수 있다. 비공개 작품은 Firestore에서 숨기지만, 이미 배포한 URL을 회수하지 않는다. 비공개 영상 보호·DRM 기능으로 간주하지 않는다. 업로드 후 작품을 저장하지 않거나 URL을 교체해도 파일은 Storage에 남는다. 관리자가 콘솔에서 사용 여부를 확인하고 정리해야 하며 자동 삭제는 하지 않는다. 전송 완료와 취소가 맞물리면 완료된 객체가 남을 수 있다.

Storage 에뮬레이터: `firebase emulators:exec --only storage --project demo-streamlab-admin 'npm --prefix admin run test:storage'`. 배포: `firebase deploy --only storage,hosting --project streamlab-ios-eba4f`.

작품 ID는 변경하지 않는다. 수정은 Firestore transaction과 revision으로 다른 창의 덮어쓰기를 막는다. 삭제 대신 비공개로 전환한다. 비공개 전환은 이후 목록·상세·재생 시작 조회에 반영되며, 이미 전달한 URL이나 재생 중인 플레이어 권한을 회수하지는 않는다. 공개 필드에 비밀 키나 비공개 서명 URL을 저장하지 않는다.

초기 카탈로그는 공개 작품 최대 200개를 대상으로 한다. 홈·검색·목록 요청마다 제한된 결과를 읽고, 페이지는 이 결과 내에서 나눈다. 201개가 반환되면 누락을 숨기지 않고 오류를 낸다. 본격적인 대규모 서비스 전에 서버 페이지네이션·검색 인덱스·읽기 예산을 재설계해야 한다. Firebase 홈은 탭 복귀와 포그라운드 복귀 시 공개 목록을 다시 조회한다. 홈을 계속 보고 있으면 60초 간격으로 조회하며 화면을 벗어나거나 앱이 비활성화되면 주기 조회를 중지한다. 서버 오류 시 Mock 작품으로 대체하지 않는다.

**사용자 계정, 프로필, 찜, 진도 동기화, 재생 grant/키 상태는 기존 데모 구현이다.** 키즈 등급 필터는 앱의 표시 정책이며 서버의 법적 연령 인증이 아니다. Firebase Auth는 이번 단계에서 관리자 웹 로그인에만 사용한다. Firebase에 등록한 HTTPS HLS 작품은 상세에서 다운로드할 수 있다. 다운로드 탭은 저장 시점의 영상과 등급을 보관하고 해당 프로필에서 만료 전 로컬 패키지를 재생한다. 공개 취소는 이미 저장된 패키지를 즉시 회수하지 않는다. 등록한 MP4도 상세의 작품 다운로드에서 저장할 수 있다. 백그라운드 파일 전송 완료 시 HTTP 응답·크기·MP4 헤더를 검사하고, 다운로드 탭에서 프로필별 로컬 파일을 재생한다. 기존 `StreamLab` Scheme의 다운로드·오프라인 기능은 유지된다.

프로필 선택 직후에는 현재 네트워크 경로가 연결돼 있으면 홈, 끊겨 있으면 다운로드 탭을 연다. 새 프로필 세션마다 첫 탭을 정하며, 사용 중 연결이 바뀌면 현재 탭을 유지한다.

6. 홈과 상세의 ‘영상 재생’에서 등록한 영상·하단 시간·탐색·닫기를 확인한다. 이 테스트는 실제 Firestore/HLS 연결이며 실제 유료 권한/DRM 검증은 아니다.
7. 비공개 전환 후 앱 재실행 시 사라지고, 새 재생 조회가 허용되지 않는지 확인한다. 이미 열린 재생의 즉시 중단은 범위 밖이다.

Firebase Scheme으로 설치한 앱은 Xcode에서 실행을 중지한 뒤 iPhone 홈 화면 아이콘으로 열어도 같은 공개 카탈로그를 사용한다. Run은 FirebaseDebug, Profile과 Archive는 FirebaseRelease이며 완성된 앱의 Info.plist에 카탈로그 선택을 기록한다. 일반 StreamLab Scheme으로 다시 설치하면 데모 카탈로그가 기본값이다.
