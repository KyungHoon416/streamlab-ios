# F06/F09/F10 복합 검증

기준 5203dcf. 이전 원격 run 41175096564는 Core 성공/iOS 실패로 확인했다. iOS 실패는 F05에서 AVPlayer 자체가 5초 내 weak nil이 되지 않은 한 건이다. 모델 해제는 실패하지 않았다. 참조 보유자의 정확한 스택은 이 로그만으로 식별할 수 없다.

## 수정과 검증 범위

- MediaPlayer removePlayer로 강제 해제를 시도했으나 로컬에서 KVO 미등록 observer 예외를 재현하여 **해당 변경은 폐기**했다. 앱 소유 모델 해제, item=nil, rate=0, Now Playing session=nil은 유지해서 검사한다. 이를 AVPlayer 전체 누수 없음 판정으로 바꾸지 않는다.
- F10: 기존 코드에 없던 failedToPlayToEndTimeNotification 처리 추가. 정확한 item, 재생 세대, seek 세대, 활성 프로필을 검사한다. 먼저 수신한 종료는 뒤늦은 실패로 뒤집지 않고, 먼저 처리한 실패는 stop으로 세대를 무효화한다. 오래된 아이템의 실패/종료는 다음 플레이어를 바꾸지 못한다.
- F09: DEBUG offline-expired 인수는 캐시된 만료 grant 뒤에 갱신 불가를 반환한다. 기존 expired-once와 달리 재시도에서 유효 grant를 자동 생성하지 않는다. 패키지 테스트는 다운로드 source에서 4회 요청/3회 재시도 상한과 player 미생성을 확인한다. 실제 파일/UI는 별도 네이티브 다운로드 테스트가 확인한다.
- F06: 실제 2개 OS 전송이 package 경로를 받은 뒤 하나에 전송 실패 원인+cancel, 다른 하나에는 0 용량 읽기를 주입한다. 실제 콜백/파일 정리/저널을 사용한다. 1GB 정책상 두 500MB 예약+양수 pinned 파일은 동시 수용 불가하므로, 정리 후 재다운로드·고정·저용량 재시도 차단·용량 회복을 같은 시나리오의 후속 단계로 검증한다.
- F10은 bundled AVPlayer와 sidecar 자막 및 AVFoundation 실패/종료 알림의 6개 순열이다. 실제 망 차단/HLS 트랙 로딩 실패와 같다고 주장하지 않는다.

## 다운로드 화면에서 재현한 결함

F09 모델 테스트는 통과했지만 실제 파일/UI 테스트에서 재시도 후 다시 만료·남은 3회가 표시됐다. DEBUG 경계 로그에서 서로 다른 model UUID에 explicitSource=true load가 연속 발생하고 retry 호출은 없음을 확인했다. 다운로드 cover의 내용 재구성 때 모델이 교체되는 경계를 확인했다. DownloadsView가 모델을 실제 dismiss까지 보관하고 PlaybackView는 주입된 모델을 재시작/중지하지 않도록 수명을 분리했다. 파일과 모델을 하나의 presentation item으로 전달하고 실제 닫기/취소 및 세션 무효화에서는 정리한다. 정상 다운로드 재생·재실행·삭제 회귀도 함께 실행한다.

첫 F06 UI는 실패 파일 정리 이후 화면 위쪽 버튼을 찾지 못해 실패했다. 전용 bounded 양방향 reveal로 테스트를 보완했고 앱 스크롤 동작은 바꾸지 않았다. F09 회전 대기 보강만으로는 문제가 해결되지 않아 위 모델 수명 변경을 진행했다.

반복 실행의 F06 실패는 현재 계정이 비어 있어도 이전 테스트 계정의 고정 파일 339,144,704바이트가 기기 전체 예산에 남아 있었기 때문이다. 해당 파일을 지우거나 제품 예산을 변경하지 않았다. 복합 검증 스크립트는 기본적으로 전용 시뮬레이터를 생성하고 끝나면 자신이 만든 기기만 정리한다. `SIMULATOR_ID`를 지정하면 기존 기기를 보존하여 사용하며, 이때 기기 전체 저장 조건은 호출자가 준비해야 한다. 테스트 계정 자체는 실제 로그아웃/로그인 정리 경계를 거친다.

다운로드 오류가 cover 진입·회전과 겹칠 때 활성 상태의 팝업 재시도 탭이 실제 retry 명령으로 이어지지 않는 현상도 반복 재현했다. UIKit 내부 원인을 확정하지는 않는다. 다운로드 cover는 추가 오류 팝업 대신 기존 화면 내 오류 안내·재시도·닫기 UI를 사용한다. 일반 데모/HLS 진입의 기존 오류 팝업은 유지한다.
