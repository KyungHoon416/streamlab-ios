# 재생 도중 권한 만료 검증

2026-11-01

## 변경

기존 시작 직전 검사만으로는 재생이 길어질 때 만료된 grant로 계속 재생할 수 있었다. 수락한 grant를 PlaybackModel이 보관하고 기존 250ms 샘플링, 화면 복귀, 재생/탐색 및 오디오 인터럽트 복구 전에 검사한다. 만료 시 아이템·Now Playing·파일 lease를 기존 실패 경로로 정리한다. 자동 갱신은 없으며 사용자의 제한된 수동 재시도만 새 권한을 요청한다. 정상 종료된 영상의 ended 상태는 유지하고 다시 재생할 때 검사한다.

## 검증

- iOS 패키지 22개: PASS. 새 3개는 재생 중/일시정지 중/복귀 시 정확한 300초 경계 만료를 주입해 아이템 정리·자동 갱신 없음·재시도·닫은 세션 뒤 새 재생을 검사한다.
- 앱 UI 1개: PASS (39.856초). 첫 grant 10초 후 만료 안내 → 재시도 → 하단 시간 2초 이상 → 닫기.
- Release iOS Simulator 빌드: PASS. 경고를 오류로 처리하고 경고 억제는 해제했다.
- 스크립트 문법·필수 14개 테스트 표식·공백 검사: PASS. 원시 로그 위치와 SHA-256은 MANIFEST.json에 기록했다.
- 원격 CI: 푸시 후 확인 예정.

## 한계 및 실기기

실제 서버/FairPlay/신뢰 시계가 아닌 기존 Mock 경계다. 기본 5분은 과제 요구 기간이 아닌 기존 데모 정책이다. OS suspend 동안 만료 순간 실행을 보장하지 않으며 복귀 시 검사한다. 기존 주기 작업을 재사용해 추가 타이머를 만들지 않는다.

[실기기 확인](../../PLAYBACK_ENTITLEMENT_QA.md)의 새 Debug 인수로 첫 grant만 10초 후 만료시켜 확인한다. 이번 변경의 실기기 결과는 아직 받지 않았다.
