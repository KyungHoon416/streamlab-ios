# 잠금 상태 시작 시 로그인 복원 대기

## 근거와 변경

실기기 Keychain 잠금 진단 PASS(사용자 보고)를 기록한 뒤, 운영 서버 없이 확인할 수 있는 잠금 상태 앱 시작 경계를 보완했다. 기존 CatalogAccount.prepare는 시작 즉시 복원을 완료 처리할 준비 상태로 고정하고, Keychain 잠금 오류도 일반 복원 실패로 표시했다. 앱 루트에는 잠금 해제 후 prepare를 다시 호출하는 연결이 없었다. 이는 코드 검사에서 확인한 복구 경로 누락이며 실제 잠금 cold launch 장애 재현을 주장하지 않는다.

- protected data가 사용 불가하면 저장소를 열기 전 복원 대기 화면을 표시한다. 새 로그인으로 기존 토큰을 덮어쓰지 않는다.
- 잠금 해제 알림과 foreground 활성화에서 복원을 재시도한다. 이미 복원한 세션은 재실행하지 않는다.
- 사전 확인 뒤 잠금이 발생한 경우에도 Keychain interaction-not-allowed 또는 protected data 사용 불가 오류는 대기로 남긴다.
- 자동 알림과 작업 타이밍이 겹칠 때 사용할 수 있도록 ‘복원 다시 시도’를 제공한다. 복원 완료 전 계정 콘텐츠와 데모 시작은 노출하지 않는다.
- Keychain 접근 수준은 WhenUnlockedThisDeviceOnly 그대로다. 잠금마다 기존 메모리 세션을 지우거나 백그라운드 다운로드를 중단하는 변경은 아니다.

## 검증 범위

새 UI 테스트는 실제 저장된 데모 로그인 상태로 앱을 재실행하되, Debug 전용 인자로 protected data 가용성 판단을 false로 만든다. 대기 중 계정/로그인 화면 미노출, 잠긴 상태 재시도, 해제 알림 수신 후 추가 로그인 없이 복원, 홈 foreground 복귀를 확인한다. 실제 iOS 키백 잠금을 강제로 재현한 테스트가 아니다.

기존 최대 글자 로그인·복원·전체 프로필 정리·오프라인 미전송 변경 정리·진단 취소 UI 테스트와 함께 실행한다. 실기기용 Release 컴파일도 확인한다. 결과와 입력 해시는 RESULTS.txt/MANIFEST.json에 기록한다.

## 사용자 확인

추가 trace는 필요 없다. 일반 실행에서는 테스트 인자를 제거하고 로그인 → 앱 재실행 → 홈에서 잠금/해제 → 탭 이동이 정상인지 확인한다.

복원 대기 UI도 직접 확인하려면 Debug Run Arguments에 `--ui-test-auth-locked-start`만 추가한 뒤 로그인된 앱을 재실행한다. ‘잠금을 해제하면 로그인 상태를 복원합니다’와 ‘복원 다시 시도’가 보이고 데모 시작/프로필은 보이지 않아야 한다. ‘잠금 해제 테스트’를 누르면 추가 로그인 없이 프로필 선택으로 이동한다. 확인 뒤 인자를 제거한다. 이 버튼은 테스트용 논리 잠금 해제이며 실제 하드웨어 보호 검증으로 계산하지 않는다.

실제 잠금 상태 OS cold launch/재부팅 직후 최초 잠금 해제 전 상태, 운영 서버/TLS는 여전히 별도 범위다. 이번 진단 PASS와 앱 복원 흐름 검증을 전체 과제 완료로 확대하지 않는다.

## 실행 결과

- 첫 전체 실행: 기존 5개 PASS, 새 잠금 대기 테스트 1개 FAIL. 대기 컨테이너의 account-restoring 식별자를 ProgressView 자체로 옮겼다.
- 수정 후 일반 로그인 복원·로그아웃 재실행과 새 잠금 대기/해제 복원을 집중 재검증하여 2개 모두 PASS(exit 0). 동일 새 테스트가 통과해 버튼 식별 문제의 해결을 확인했다.
- 최종 Release 실기기 대상 컴파일 PASS. 진단/모의 잠금 해제 심볼이 Release에 없는지 확인했다.
- 시나리오별 최종 상태는 6개 PASS지만 최초 전체 실행 자체는 실패로 보존하며 ‘전체 실행 한 번에 6개 PASS’로 기록하지 않는다. 이번 마지막 변경은 대기 ProgressView 식별자 위치뿐이라 통과한 데이터 정리 테스트를 반복하지 않았다.
- 원시 결과: Docs/Validation/demo-authentication-g1BuJn/ 및 Docs/Validation/auth-unlock-focused/. Git에는 요약과 해시를 보존한다.

## 실기기 후속 확인 — 2026-10-31

사용자가 최신 코드에서 로그인 후 앱을 다시 실행해도 상태가 유지되고, 홈에서 잠금·해제한 후 탭 이동도 정상이라고 보고했다. 해당 일반 실행 회귀를 사용자 보고 기준 검증 완료로 기록한다. 이번 확인의 기종/OS 및 별도 캡처는 미제공이다. 이 보고는 OS가 잠금 상태에서 새 프로세스를 시작하는 cold launch나 재부팅 후 최초 잠금 해제 전 동작의 증거는 아니다.
