# 운영 서버 없는 로그인·로그아웃 / 잠금 실기기 확인

## 준비

최신 main을 가져온 뒤 StreamLab Scheme의 Run을 Debug로 빌드한다. Scheme → Edit Scheme → Run → Arguments → Arguments Passed On Launch에 `--diagnose-keychain-lock` 하나를 추가하고 체크한다. 기존 인자/서명 설정은 그대로 둔다. Instruments나 새 trace는 필요 없다.

잠금 진단은 Debug 전용이다. Release에는 화면·더미 검증 코드가 포함되지 않는다. iPhone 암호가 설정되어 있어야 하며 iPhone 미러링은 종료하고 폰에서 직접 조작한다. 잠금 검증 때는 앱을 실행한 뒤 Xcode 디버거 연결을 해제하고 앱을 다시 열어 진행하는 편이 좋다. Run의 Debug executable을 해제해도 된다. 앱 실행 인자 적용 여부는 오른쪽 아래 ‘잠금 검증’ 버튼으로 확인한다.

## 1. 로그인 연결

1. 앱의 ‘데모 시작’ → 프로필 선택 → 홈 진입을 확인한다. 실제 서버 로그인이나 비밀번호 인증이 아니다.
2. 앱을 종료하고 다시 열어 데모 시작 없이 프로필 선택이 나오는지 확인한다.
3. 홈에서 기기를 잠그고 약 10초 후 해제한다. 앱으로 돌아왔을 때 홈·탭 조작이 되고 불필요하게 로그아웃되지 않는지 확인한다.

## 2. 실제 Keychain 잠금 보호

1. ‘잠금 검증’ → ‘검증 시작’을 누른다.
2. **‘준비 완료’가 표시된 뒤** 측면 버튼으로 잠근다. 준비 전에 잠그면 읽기 기준값을 확인할 수 없다.
3. 잠금 화면을 들여다보며 Face ID가 바로 풀리지 않도록 두고 약 10~15초 후 직접 잠금을 해제한다. 앱으로 돌아온다.
4. `PASS: 잠금 중 읽기 차단 · 해제 후 동일 값 복구 · 더미 삭제 확인`을 확인한다.
5. 결과 화면을 캡처해 보내고 기종/iOS 버전, 잠금 시간을 알려준다. ‘미확인’도 표시된 문구 그대로 보내면 된다. 미확인을 성공으로 기록하지 않는다.

전용 namespace `com.streamlab.diagnostics.lock-probe.v1`의 더미 항목만 사용한다. 실제 데모 계정의 토큰은 조회/변경하지 않는다. 잠금 중 protected data가 unavailable이고 실제 Keychain 읽기가 -25308로 거부된 경우만 차단으로 인정한다. 이후 해제 상태에서 원래 값과 일치하는지, 삭제 뒤 nil인지 확인한다. 시뮬레이터에서는 하드웨어 잠금 PASS를 내지 않는다.

백그라운드 실행 시간이 만료되거나 잠금 차단을 관측하지 못하면 미확인이다. 더미 정리 실패가 표시되면 잠금 해제 후 ‘검증 시작’을 다시 누르고 준비 완료 후 ‘중단 및 더미 정리’를 누른다. 앱 강제 종료로 진단이 중단되어도 다음 시작은 동일한 전용 더미 항목을 먼저 삭제한다. 진단 중 앱 삭제를 정리 방법으로 사용하지 않는다.

## 3. 로그아웃 연결

기존 로컬 기록을 삭제하는 **실제 로그아웃**이다. 확인용 찜/검색/진도를 만든 뒤 진행한다.

1. 프로필 A와 B에서 각각 찜·검색 기록을 만든다.
2. 비행기 모드를 켜고 찜을 변경한 뒤 로그아웃을 확정한다.
3. ‘데모 시작’ 화면으로 돌아오는지 확인한다. 앱 종료/재실행 뒤에도 자동 로그인되지 않아야 한다.
4. 네트워크를 복구하고 데모 시작 → A/B 프로필에서 이전 기록이 되살아나지 않는지 확인한다.
5. 완료 후 진단 Arguments를 해제한다.

## 범위

위 1·3의 일반 흐름과 오프라인 정리는 별도 simulator UI 회귀로도 확인한다. 위 2의 실제 잠금 보호는 실기기 결과가 필요하다. 일반 앱을 잠갔다 여는 것만으로는 ‘잠금 중 Keychain 읽기 거부’를 증명할 수 없다. 잠금 상태에서 OS가 앱을 새로 실행하는 상황, 재부팅 직후 최초 잠금 해제 전 접근, 운영 endpoint/TLS 인증은 별도 범위다.

Apple의 [WhenUnlockedThisDeviceOnly](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly) 정책은 잠금 해제 상태에서만 접근하도록 한다. 이 앱은 해당 정책을 유지하며, 검증 편의를 위해 AfterFirstUnlock으로 완화하지 않는다.
