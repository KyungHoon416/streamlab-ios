# Mock 재생 권한·만료·키 상태 연결

기준 407bb5a에서 작업. 과제 원문의 A2/C2 Mock 인터페이스 요구를 확인하여 기존 프로필 제한/다운로드 파일 만료와 별도로 추가했다.

## 동작

- 계정·프로필·작품·미디어 범위와 권한/시각/키 상태를 검사한다. 만료 경계에서 거부한다.
- 취소된 요청의 늦은 성공 응답을 거부하고, 세대·활성 세션을 확인한다. 진도 조회 이후 플레이어 생성 직전에도 재검사한다.
- 만료·키 사용 불가·갱신 실패를 안내하고 기존 제한된 수동 재시도로 새 Mock grant를 요청한다.
- 다운로드 파일 만료·lease 검사는 그대로 유지한다. 권한 갱신으로 만료된 파일을 우회하지 않는다.

## 검증 및 수정 이력

- Core 집중 정책 테스트 7개 PASS: 범위 4필드, 만료 경계, 거부/키 상태, 잘못된 시각, 갱신 실패/복구, 지속 거부, 취소 무시 후 도착한 성공 응답.
- 전체 Core 실제 통과 244개, 조건부 HTTP/Keychain 통합 11개 SKIP. XCTest 31개, Swift Testing 개별 PASS 213개를 합산했다.
- iOS 플레이어·Now Playing 테스트 10개 PASS. 새 테스트는 expired/keyUnavailable/denied/renewalFailed 각각 AVPlayer nil/탐색 불가를 확인하고 수동 재시도 후 실제 번들 영상 재생을 확인했다.
- 최초 UI 실행: 4개 중 3개 실패. 기존 팝업이 HLS/미디어 리셋에만 표시되어 로컬 Mock 권한 실패에는 나타나지 않았다. 권한 오류 플래그로 보완했다. 권한 차단 자체는 유지되었고 누락된 팝업 연결을 수정했다.
- lifecycle 실행 스크립트의 테스트 개수 기대값이 뒤처져 exit=0인데도 FAIL로 판정했다. 실제 로그는 10개/0실패다. 10개 및 신규 권한 테스트의 PASS를 확인하도록 수정하고 실제 로그 기반 판정 4개를 확인했다. 원래 결과 파일은 실패 이력을 보존한다.
- 새 entitlement UI 스크립트 결과 판정 6개 PASS(정상, 비정상 종료, 필수 테스트 각각 누락).
- 최종 UI 4개 PASS: 만료/키 오류/갱신 실패 안내 후 재시도 재생, 승인 대기 중 닫기 및 키즈 재열기. 원시 결과 `Docs/Validation/playback-entitlement-ldrS1F/`.
- 최종 Release 실기기 대상 컴파일 PASS(warnings-as-errors, 서명 없는 컴파일). 빌드 바이너리에서 Debug 오류 주입 인수 3개가 제외됨을 확인했다.
- bash 문법 및 git diff 공백 검사 PASS. Xcode 27.0, iOS 26.4 simulator 환경이며 신규 권한 흐름의 실기기 확인은 아직 미실시다.

## 범위와 다음 확인

기본 Mock grant는 로컬 시계로 5분 유효한 데모 값이다. 시작 시 검증만 하며 재생 중 만료 타이머, 영속/신뢰 라이선스, HTTP playback/session, FairPlay 키 취득/복호화는 구현하지 않았다. 실제 운영 DRM이나 F09 전체 완료를 주장하지 않는다. 번들 데모 오류/복구 UI와 실제 저장 HLS 오프라인 만료 조합은 다른 검증이다.

[실기기 확인 순서](../../PLAYBACK_ENTITLEMENT_QA.md). 새 trace는 필요 없으며 Debug 인수로 만료 안내와 재시도를 확인할 수 있다. 실제 다운로드 만료는 기존 QA를 따른다.
