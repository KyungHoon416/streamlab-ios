# 미식별 18.92ms 추가 분석

2026-10-31. c4-current-home-scroll-1.trace의 동일한 초기 Hang 구간을 사용했다. 원본 trace/앱 동작을 바꾸지 않았다.

## 배타적 호출 문맥 분류

| 호출 문맥 | 이벤트 수 | Blocked 교차 시간 |
|---|---:|---:|
| 이름 기반 벡터 아이콘 조회 | 43 | 6.426ms |
| Swift 런타임 처리 | 50 | 5.832ms |
| 스택 없음 | 12 | 3.110ms |
| 그 외 | 19 | 2.720ms |
| 글꼴 윤곽 처리 | 2 | 0.649ms |
| 그 외 CoreUI 리소스 처리 | 4 | 0.185ms |
| 합계 | 130 | 18.921ms |

이는 **호출 문맥 분류이며 파일 소유권을 새로 식별한 결과가 아니다.** 전체 스택에서 namedVectorGlyph/NamedImage.VectorKey → 그 외 CoreUI → FontParser → Swift runtime → 그 외 순으로 배타적으로 분류했다. 스택 없는 이벤트는 별도다. 같은 이벤트를 여러 범주의 합계에 넣지 않았다. Swift runtime 분류도 스택에 런타임이 포함됐다는 뜻이며 전체 시간이 특정 런타임 함수 자체에서 소비됐음을 뜻하지 않는다.

## 추가로 확인한 연결

- 동일 StreamLab 프로세스의 전체 syscall/VM 스택을 조회해 다른 시각에 실행된 코드 PC가 미식별 페이지에 포함되는지 확인했다. 추가 코드 이미지 대응은 0개였다. 다른 프로세스의 주소는 섞지 않았다.
- 같은 프로세스에서 성공한 mmap의 반환 주소와 길이를 fault 페이지에 대조했다. fault 이전에 만들어졌고 중간 munmap으로 해제되지 않은 범위에 62개 이벤트(10.641ms)가 들어간다. 이 수치는 위 문맥 표와 중첩되는 별도 관점이며 더해서 총 대기를 만들지 않는다.
- syscall export에는 mmap의 처음 4개 인자(주소·길이·보호·플래그)와 반환 주소가 있지만 fd/offset/path가 없다. 이 자료만으로 특정 Assets.car, 폰트 파일, 공유 캐시 경로를 복원할 수 없다. 다른 trace의 파일 경로를 가져와 연결하지 않는다.
- 벡터 아이콘 문맥에는 CUICatalog.namedVectorGlyph, CUINamedVectorGlyph, NamedImage.VectorKey, CoreUI BOM 리소스 조회가 있다. 특정 아이콘 이름/파일명은 미기록이다. 포스터 이미지 파일이라고 단정하지 않는다.
- 글꼴 문맥에는 Type1/Type2 charstring 해석, glyph outline/path 생성이 나타나지만 구체적 폰트명은 미식별이다.
- 앱 프레임으로는 CatalogTabs.body/tabContainer가 약 0.923ms의 이벤트 스택에 포함되고, Session/MyListStore metadata 경로가 약 0.110ms에 포함된다. 부모·자식 프레임은 중첩되므로 합산하지 않는다. 앱 프레임이 스택에 있다는 사실만으로 잘못된 반복 초기화가 증명되지는 않는다.

## 수정 판단

기존 18.92ms는 단일 파일/작업이 아니라 아이콘 리소스, 런타임/메타데이터, 글꼴 등 여러 처리 문맥으로 나뉜다. 제거 가능한 중복 요청이나 필요 없는 앱 코드가 확인되지 않았다. 따라서 아이콘 교체·탭 구조 변경·예열·초기화 지연 같은 추측성 변경은 하지 않았다.

현재 기록에서 가능한 주소·스택·mmap 연결은 확인했다. **정확한 파일명 식별은 이 trace에 없는 매핑 정보 때문에 더 진행할 수 없다.** 같은 파일로 계속 세부 파일명을 추정하거나 해결 완료로 기록하지 않는다. 지금 추가 실기기 측정은 요청하지 않는다. 초기 지연은 미해결 상태로 유지하되, 수정 근거가 없는 재설계보다 과제의 다른 검증 항목을 진행하는 것이 타당하다.
