# C4 에너지·파일 I/O 확인（2026-10-31）

## 결론

다운로드 영상은 재생 실패가 아니라 사용자 재생 확인 생략이다. 다운로드·삭제 분석에는 영향이 없다. 셀룰러 측정이라는 사용자 조건을 적용했다. 파일 두 개 모두 TOC export 성공, 각각 하나의 Run을 확인했다. 원본 trace는 수정하지 않았다.

## 에너지 파일

c4-hls-power-1.trace: 09:54:23 KST 시작, 213.166615초. 전체 열 상태 Fair.
TOC 템플릿은 Animation Hitches. form.template의 instruments-by-run-number를 별도로 해석했으며 Hangs, Hitches, Thermal State, Points of Interest, Metal Display, CPU sampler, Thread Activity만 존재한다. Power Profiler 계측과 전력 데이터 표는 없다. 파일 이름만 power이며 실제 전력 측정 증빙이 아니다. CPU/열 상태를 소비전력·배터리 소모량으로 대체하지 않는다. HLS 재생 실패로 해석하지 않는다.

UI 확인을 시도했으나 잠금 해제 이후 화면 캡처 오류가 발생했다. 최종 계측 구성 판정은 UI 추측이 아닌 저장된 keyed archive의 instrument 목록과 TOC에 근거한다. manifest.json에 입력 해시와 구성 목록을 보존했다.

## 다운로드·삭제 파일

c4-download-fileio-1.trace: 10:27:40 KST 시작, 72.209953초. 템플릿 이름은 Animation Hitches지만 구성에 fs-syscalls(File Activity)가 실제 추가되어 있다. FsSyscall 12,052행, RawVirtualfilesystemCalls 12,594행, VnodeToPaths 11,617행을 확보했다. 서로 다른 표를 합산하지 않고 FsSyscall만 집계했다. 해당 FsSyscall의 프로세스는 전부 StreamLab이다.

전체 열 상태 Serious. 시간 값은 이 열 상태에서의 관측이며 정상 온도 성능 목표로 판정하지 않는다.

이는 앱 프로세스에 관측된 논리 I/O다. 물리 디스크 쓰기량이나 HLS 다운로드 총 용량이 아니다. 영상 파일 쓰기를 맡는 백그라운드 서비스의 전체 I/O를 이 기록에서 확보하지 못했으므로 수 KB만 다운로드했다고 해석하지 않는다.

### 다운로드

- 사용자 시작 시각 15초와 일치하게 offline-downloads.json이 15.048/15.138/15.195초에 각각 1,203/1,208/1,384바이트 쓰였다. fsync/rename을 포함한 원자적 기록 갱신을 확인했다.
- 사용자 완료 시각 40초와 일치하게 40.085초에 1,418바이트 기록 쓰기가 관측됐다. 해당 journal 쓰기와 rename의 error는 0이다.
- 전송 중 호출은 getattrlist 3,831회, lstat64 2,872회, statfs64 2,018회가 대부분이다. 크고 지속적인 앱 데이터 쓰기보다는 파일/공간 메타데이터 조회가 많다. 저장 공간 갱신 경로의 호출 빈도는 후속 최적화 후보이며, 이번 기록만으로 특정 함수의 버그나 과도한 물리 I/O라고 단정하지 않는다.

### 삭제

- 실제 movpkg 삭제 호출은 60.853~60.970초, 약 117ms 구간에 있다. 사용자 메모 50초와 차이가 있으나 클릭 이벤트와 대조되지 않아 10초 처리 지연이라고 판정하지 않는다.
- movpkg 내부 unlink 성공 191건, 디렉터리 대상 unlink 오류 4건 이후 rmdir 성공 4건. 최상위 movpkg rmdir도 60.970초에 error=0으로 완료됐다. 디렉터리에 대한 초기 unlink 실패만을 최종 삭제 실패로 세지 않는다.
- 60.971초 journal이 987바이트로 갱신됐다. 61.3초 이후 파일시스템 표에 남은 호출은 socket 6건이며 영상 파일의 지속 쓰기는 관측되지 않는다.
- 이 결과는 패키지 삭제 호출 성공을 보여주지만 파일시스템 용량 스냅샷이 없어 정확한 회수 바이트 수와 물리 저장장치 반영 시점은 증명하지 않는다. 앱 밖의 다운로드 서비스 전체 상태 또한 보증하지 않는다.

## 다음 측정

File Activity는 재측정하지 않아도 다운로드 기록 갱신과 패키지 삭제 증빙으로 사용할 수 있다. 정상 온도 디스크 성능/전체 서비스 I/O/회수 용량을 별도로 요구할 때에만 추가 측정한다.

에너지는 새 문서(File → New)에서 Power Profiler 템플릿을 선택해야 한다. 기기를 식힌 뒤 동일 빌드·셀룰러 조건에서 홈 30초 → HLS 스트리밍 2분 → 홈 30초. c4-hls-power-2.trace로 별도 저장한다. 재빌드 불필요. 녹화 전에 Power Profiler 관련 트랙이 보이는지 확인한다. 해당 기기에서 비활성/지원 불가라면 Animation Hitches로 대체하지 말고 그 상태를 확인한다. 충전/연결 상태와 밝기는 기록 중 고정하고 메모한다. 기존 파일은 덮어쓰지 않는다.

다운로드 영상의 재생 확인은 이번 파일 I/O 검증의 필수 동작이 아니며, 재생 실패로 기록하지 않았다. C4 전체 성능 PASS는 미판정. 코드 수정/커밋/푸시 없음.
