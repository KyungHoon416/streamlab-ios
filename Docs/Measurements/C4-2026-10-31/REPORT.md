### 해석 및 현재 코드 상태

entry3는 compact 변경 이전 기준 기록이다. compact1/2는 Compact 표식이 있는 기록이며, repeat1~3는 같은 compact 빌드로 재실행했다는 사용자 확인이 있는 기록이다. staged1에는 StartupNavigationStaged와 NavigationStageReady 표식이 있다. 표식은 구성을 확인하지만 측정 바이너리의 정확한 Git 커밋을 증명하지 않는다.

compact2의 큰 지연은 기존 분석에서 메인 스레드 Blocked 약 599ms 중 약 578ms가 파일 페이지 로딩과 겹쳤다. 반복 기록은 초기 Update 108~118ms 수준으로 돌아왔다. 따라서 지연이 실행마다 계속 증가한다거나 compact 코드만의 문제라고 결론 내릴 수 없다. [Blocked 분석](../../HOME_CHROME_BLOCKED_ANALYSIS.md), [공통 CPU 비용](../../HOME_INITIAL_CPU_ANALYSIS.md).

staged1은 최대 Update가 90ms로 작지만 홈 레이아웃까지 343ms이며, 초기 구성을 나눈 추가 갱신이 포함된다. 단일 긴 갱신 감소만으로 개선 성공이라고 판단하지 않는다. 현재 기본 동작은 `77681bf`에서 즉시 구성으로 복원했고 단계 구성은 진단 옵션으로 남겼다. 사용자가 2026-10-31 홈 진입·탭 왕복·프로필 변경·다운로드 알림 이동 정상임을 확인했다. **기능 회귀 확인 완료이며 복원 이후 성능 수치 검증은 별도다.** [후속 수정](../../HOME_NAVIGATION_FOLLOWUP.md).

## 재현 및 검증

[도구 사용법](../../FRAME_SUMMARY.md)에 따라 manifest의 각 입력 TOC/events 해시와 Run을 확인하고 window_start_s/window_end_s를 --start/--end로 지정하면 각 JSON을 재생성할 수 있다. XML은 원래 로컬 exports를 사용한다. 입력 파일 해시는 동일 파일 여부 확인용이며 기기 조건이나 바이너리 커밋을 증명하지 않는다.

검증: 7개 집계 모두 available; staged1의 Hitch 3개·합계 133.361332ms 및 최대 Update 90.263875ms가 기존 분석과 일치. frame/runtime/TTFF 도구 단위 테스트 총 18개 통과. 문서/집계 산출물 변경이므로 Xcode 빌드와 실기기 재측정은 반복하지 않았다.
