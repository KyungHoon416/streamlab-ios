# 늦은 재생 권한 응답·재시도 소진 경계

기준 5bb9c00. 사용자의 만료 안내 후 실기기 재시도/시간 진행/닫기 정상 확인을 기록한 뒤, 새 Mock 권한 경로의 취소 경계를 검증했다.

## 시나리오

- 이미 대기 중인 권한 조회를 화면 닫기로 취소한 뒤 성공 응답 전달.
- 이미 대기 중인 권한 조회를 세션 무효화로 취소한 뒤 성공 응답 전달. 앱 로그아웃에서 쓰는 세션 정리 경계이며 실제 로그인 UI 전체 시나리오와 구분한다.
- 이전 프로필의 권한 응답을 보류하고 새 프로필에서 실제 번들 영상을 재생한 뒤 이전 성공 응답 전달. 새 Now Playing 세션과 재생을 유지해야 한다.
- 권한 갱신이 지속 실패할 때 최초 요청 + 수동 재시도 3회 후 더 이상 요청/AVPlayer 생성이 없어야 한다.

HeldEntitlement는 continuation으로 응답을 보류하고 취소를 의도적으로 무시한다. 요청이 대기 상태에 도달했는지 먼저 확인한다. 늦은 응답 이후 0.5초 동안 이전 모델의 player 발행을 관찰해 재생 복원을 거부하고 최종 상태도 확인한다. 유한 시간의 iOS 통합 회귀이며 모든 스케줄링 순서의 증명으로 확대하지 않는다. Domain의 취소 후 응답 차단 테스트가 별도로 존재한다.

실기기 재측정이나 trace를 새로 요구하지 않는다. 실제 서버 라이선스·기기 간 동기화·F09 전체는 이 검증의 범위 밖이다.

## 결과

- 새로운 경계 4개 + 기존 재생/Now Playing/회전 콜백 12개 = iOS 통합 16개 PASS, 0실패.
- Xcode 27.0 / iOS 26.4 simulator, warnings-as-errors. 원시 로그: Docs/Validation/playback-session-lifecycle-RgIvzJ/.
- 결과 판정 10개 PASS: 정상, xcodebuild 실패, 개수 미달, 필수 테스트 7개 각각 누락. bash 문법 및 diff 검사 PASS.
- 앱 결함은 발견되지 않았다. 이번 변경은 테스트·결과 판정·기록이며 실행 코드 변경은 없다. Core/Release/전체 UI를 불필요하게 재실행하지 않았다.
