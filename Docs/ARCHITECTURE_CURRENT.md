# StreamLab 현재 아키텍처

2026-10-31 · 구현 기준 `d23d98dcb67980ff760054142b4901751329d740`

## 현재 시스템 한눈에 보기

StreamLab | 로컬 우선 스트리밍 데모
SwiftUI 화면과 네이티브 AVPlayer·HLS 다운로드를 결합한 iOS 앱입니다. 운영 인증·콘텐츠·동기화 서버는 연결하지 않았으며, 앱은 로컬 데모 계정과 Mock 콘텐츠를 사용합니다.

구조도는 동봉 PDF 및 HTML에 벡터로 수록했습니다.

| 현재 연결 | 구분 |
|---|---|
| 앱 기능 | 로컬 계정 복원, 프로필 격리, 홈/검색/상세, 영상 재생, 오프라인 다운로드 |
| 실제 OS 기능 | AVPlayer, 백그라운드 HLS, Keychain, 파일 저장, 완료 알림, 네트워크 배너 |
| Mock / 독립 검증 | 카탈로그·동기화 서버·재생 권한은 데모 구현. HTTP 구현은 loopback 서버로 별도 검증 |
| 아직 아님 | SwiftData DB, 운영 로그인 서버, 상용 DRM, 실제 다기기 운영 동기화 |

이 문서는 구현과 검증 상태를 함께 설명합니다. 테스트 PASS는 해당 주입·실행 범위에만 적용하며 과제 전체 완료를 의미하지 않습니다.

## 모듈과 상태의 소유권

구조도는 동봉 PDF 및 HTML에 벡터로 수록했습니다.

| 경계 | 현재 책임 |
|---|---|
| StreamLabCore | Domain은 상위 UI를 모릅니다. Presentation과 CatalogData는 Domain에 의존합니다. |
| StreamLabUI | CatalogFeature는 Core와 DesignSystem을 사용합니다. iOS 18 이상, Swift 6 패키지 구성입니다. |
| CatalogAccount | Keychain의 데모 로그인 상태와 보호 데이터 잠금, 로그아웃 정리를 조정합니다. |
| CatalogSession | 프로필을 선택할 때마다 새 ID를 만듭니다. 화면·플레이어·진도·검색·리스트 작업을 묶고 이전 세션을 무효화합니다. |
| 화면 상태 | 각 탭은 독립 navigation path를 가집니다. 처음 선택한 탭의 하위 화면을 구성한 뒤 상태를 유지합니다. |
| 이번 재생 수명 수정 | 다운로드 목록이 파일과 PlaybackModel을 함께 보관합니다. cover 재구성으로 재시도 예산이 초기화되지 않게 하고 실제 dismiss 때 정리합니다. |

그림은 책임 흐름을 요약한 것으로 전체 import 그래프는 아닙니다. 정확한 의존 관계는 두 Package.swift에 정의돼 있습니다.

## 로컬 저장과 데이터 정합성

로컬 저장 계층은 구현돼 있습니다. 현재는 SwiftData/SQLite 테이블 대신 목적별 저장소를 사용하며, 메타데이터와 영상 파일을 분리합니다.

| 데이터 | 저장 방식 | 정합성 경계 |
|---|---|---|
| 리스트·최근 검색·진도 | DurableMutationStore의 계정/프로필별 JSON 저널 | 로컬 투영값과 미전송 요청을 하나의 atomic 교체로 저장 |
| 동기화 서버 상태 | 기기 내부 MockMutationServer JSON | revision·중복 요청·충돌 정책을 재현. 운영 서버 아님 |
| 언어·호환 설정 | UserDefaults + Codable | 프로필별 설정. 진도 저장은 앱의 durable 모드 사용 |
| 다운로드 기록 | offline-downloads.json | 상태·소유자·경로·만료·고정 여부 저장, OS task와 복구 |
| 영상 본체 | OS가 관리하는 .movpkg | 컨테이너 경로 검증, 재생 lease, 취소/삭제 후 정리 |
| 로그인 자격·로그아웃 | Keychain + 로그아웃 표식 파일 | 잠금 시 복원 보류, 미완료 로그아웃은 복원보다 우선 |

### 오프라인 변경의 전송 흐름

구조도는 동봉 PDF 및 HTML에 벡터로 수록했습니다.

응답 유실 시 같은 요청을 재전송하고, 서버 revision과 충돌 정책으로 수렴시킵니다. F03은 100개 요청의 ACK 유실 뒤 저장소 재구성·재전송을 확인했습니다. 실제 iOS 프로세스 kill 시점과 동일한 시험은 아닙니다.

현재 앱은 로컬 Mock 서버에 동기화합니다. AuthenticatedHTTPClient와 HTTPMutationTransport는 구현 및 실제 loopback HTTP 검증이 있지만, 이를 운영 서버 연결 완료로 해석하지 않습니다.

## 영상 재생과 복구 흐름

구조도는 동봉 PDF 및 HTML에 벡터로 수록했습니다.

| 주제 | 구현 |
|---|---|
| 탐색과 하단 시간 | seek 세대와 완료를 구분하며 드래그 미리보기 값이 실제 재생 시간을 계속 덮지 않도록 처리합니다. |
| 권한 오류 | 플레이어 생성 전 차단합니다. 수동 재시도 예산은 3회이며 닫고 새로 열기 전까지 유지합니다. |
| 다운로드 오류 UI | 회전/cover 진입과 겹치는 팝업 대신 화면 안 오류 안내·재시도·닫기를 사용합니다. |
| 종료/실패 경쟁 | 현재 item과 재생·seek 세대가 일치하는 알림만 수용합니다. 수용한 종료를 뒤늦은 실패가 뒤집지 못하게 합니다. |
| 닫기·프로필 전환 | player/item, observer, task, Now Playing 소유권, 다운로드 재생 lease를 정리합니다. |
| 검증 범위 | F10은 실제 AVPlayer에 자막 변경·실패·종료 알림의 6개 처리 순서를 주입합니다. 실제 망 차단의 모든 타이밍을 보증하지 않습니다. |

이번 수정은 failedToPlayToEndTimeNotification 처리 누락과 다운로드 재생 모델 수명 경계를 보강했습니다. 과거의 seek·재생 시간 및 회전 오류 콜백 수정은 그대로 유지합니다.

## 실기기 확인과 근거

### 이번 변경 후 필요한 확인

1. 최신 빌드에서 다운로드 완료 파일을 재생합니다. 영상과 하단 시간이 진행되고 닫으면 같은 다운로드 목록으로 돌아오는지 확인합니다.

2. Debug Run 인수에 --ui-test-entitlement-offline-expired를 추가합니다. 완료 파일을 선택하면 만료 안내가 나오고, 재시도 후 갱신 불가와 남은 2회가 표시돼야 합니다. 닫아도 파일은 유지돼야 합니다. 비행기 모드에서는 Wi-Fi도 끈 뒤 확인합니다.

3. 인수를 제거하고 앱을 다시 실행합니다. 기존 다운로드의 오프라인 재생을 확인합니다. 정상 HLS 재생 중 자막 변경·네트워크 단절 후 닫고, 연결을 복구해 새 재생이 옛 오류로 중단되지 않는지도 확인합니다.
