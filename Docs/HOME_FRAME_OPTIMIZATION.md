# 홈 진입·스크롤 렌더링 개선

## 확인한 경로

홈 진입 지연 구간 CPU 샘플에서 `CatalogSession.progressTransport()` →
`MockMutationServer.init(storageURL:)` → JSON 해석이 메인 스레드에 나타났다.
기존 `Task`는 MainActor를 상속하므로 Task로 감싼 것만으로 동기 파일 읽기가
백그라운드로 이동하지 않았다. 초기 레이아웃·시스템 프레임워크 비용도 함께
기록되어 이 경로를 전체 지연의 유일한 원인으로 단정하지 않는다.

스크롤 측정에는 offscreen render 비용 표시가 있었다. 코드에는 로드 완료 후에도
포스터 뒤에서 그라데이션·심볼을 그리는 경로와 사각형/둥근 모서리 중복 클리핑이
있었다. 특정 포스터가 측정 이벤트 전체를 유발했다고 확정한 것은 아니다.

## 변경

- `MockServerRegistry` actor가 mock 동기화 서버의 파일 읽기·JSON 해석과 캐시를
  소유한다. 생성 중 await가 없어 같은 URL의 동시 요청도 한 서버를 공유한다.
  목록·시청 기록·검색 기록의 파일 구분은 유지한다.
- 서버 준비를 기다리던 작업이 로그아웃/프로필 변경으로 취소되면 flush 전에 중단한다.
- My List 스냅샷이 동일하면 재발행하지 않아 홈의 불필요한 갱신을 줄인다.
- 포스터는 로드된 이미지와 대체 화면 중 하나만 그리며 둥근 클리핑 하나로 경계를
  제한한다. 이미지 탭 영역, 비율 채우기, 캐시 해제 정책은 유지한다.

이 변경은 SwiftData 도입이나 모든 로컬 저장 작업의 비동기화를 의미하지 않는다.
기존 로컬 journal 복원·변경 저장은 여전히 별도 개선 대상이다.

## 검증

2026-10-27 실행:

- Core: 209개 + ArtworkDataCache 7개, 총 216개 통과.
- iOS package: 서버 소유권/파일 손상/목록 발행 3개 + 이미지 캐시 2개 통과.
- Release 기기용 빌드: 경고를 오류로 처리하는 설정으로 성공.
- UI: 포스터·검색 썸네일 상세 진입, 프로필별 목록 저장, 고대비·동작 줄이기 통과.
  마지막 동일 목록 발행 억제 변경 후 목록/포스터 UI 2개도 재검증 통과.

자동 테스트는 기능 회귀 확인이며 실기기 프레임 성능 개선 수치를 대신하지 않는다.

## 실기기 재측정

동일 프로필·데이터·Release 구성으로 다음을 별도 기록한다. 재설치로 데이터를
지우면 기존 파일 읽기 비용과 비교할 수 없으므로 기존 데이터를 유지한다.

1. 앱 종료 후 Instruments Animation Hitches로 시작하고 프로필 선택 → 홈 진입을
   기록한다. `frames-home-entry-fixed.trace`로 저장한다.
2. 새 기록에서 홈 진입 후 10초 대기 → 스크롤 5왕복을 수행한다.
   `frames-home-scroll-fixed.trace`로 저장하고 기록 기준 스크롤 시작 시각도 남긴다.
3. 초기 메인 스레드 호출 스택과 스크롤 구간의 hitch 횟수/지속 시간, offscreen
   render 이벤트를 비교한다. 개선 전후 기록 길이가 달라 전체 합계만 비교하지 않는다.

수정 후 실기기 측정 전에는 끊김 제거, 개선률, C4 전체 통과를 선언하지 않는다.

## 후속 수정: 초기 화면 준비 비용

수정 후 trace의 초기 CPU 호출 스택에서 다음 경로를 확인했다.

- 계정 복원 중 `OfflineDownloadStore.activateStore`의 무조건적인 journal 저장.
- 프로필 선택 시 `DurableMutationStore.defaultDirectory`의 반복 파일 시스템 조회.
- 첫 콘텐츠 갱신 시 `CatalogArtwork.url`의 번들 경로 조회.
- 같은 구간의 SwiftUI 레이아웃·시스템 심볼 준비. 이는 한 함수의 실행 시간으로
  환산할 수 없고, 동기 journal 복원도 여전히 일부 남아 있다.

이번 변경은 사용 전 검색/다운로드 NavigationStack의 생성을 지연하고 첫 선택 후
유지한다. 검색 기록의 미전송 변경 동기화와 다운로드 백그라운드 세션 복원은
기존 시점에 유지한다. 홈에 필요한 목록과 이어보기 기록도 기존처럼 복원한다.

앱 저장소 경로는 첫 성공 결과만 프로세스 내에서 재사용한다. 실패는 캐시하지 않고,
실제 쓰기 작업은 기존대로 상위 디렉터리를 생성한다. 번들 포스터 경로 6개도
재사용한다. 계정 차단 해제가 없는 정상 다운로드 복원에서는 변경 없는 journal을
재저장하지 않는다. 차단 해제·만료·다운로드 상태 변경의 영속화는 유지한다.

기능 검증 후에도 수정 후 실기기 초기 진입 지연의 감소 폭은 새 trace로 확인해야 한다.
이 변경을 동기 로컬 저장의 완전한 비동기화나 초기 끊김 제거 완료로 표현하지 않는다.

후속 수정 검증(2026-10-27): Core 216개, iOS 이미지 캐시 2개,
UI 3개(첫 실행 다운로드 알림/로그아웃, 포스터 탭, 검색 페이지·탭 상태 유지) 통과.
기기용 Release 빌드 성공, 경고를 오류로 처리. 수정 후 실기기 trace는 미수집.

## 후속 수정: 포스터 레이어 및 홈 뷰 경계

냉각 후 누적 trace의 새 Run만 분석하고, 각 hitch의 swap ID를 update/render
테이블에 연결했다. 초기 프레임은 app update/SwiftUI 레이아웃이 크게 관찰됐고,
스크롤 프레임에도 레이아웃 갱신과 여러 offscreen pass가 함께 있었다.
CPU 샘플은 중첩 호출이므로 함수별 시간 합계나 단일 원인으로 해석하지 않는다.

- 로드된 포스터는 `GeometryReader` + SwiftUI 이미지/마스크 대신 단일 UIView의
  CALayer contents로 표시한다. aspect-fill, 둥근 모서리, 이미지 경계는 유지한다.
  추가 래스터 캐시나 이미지 복사본을 만들지 않고 기존 디코딩·캐시 정책을 사용한다.
- 그림은 터치/접근성을 받지 않으며 기존 부모 NavigationLink가 카드 전체를 담당한다.
- 홈 추천 영역과 가로 목록을 `HomeHero`/`HomeRail`이라는 구체적 View로 분리하여
  큰 홈 뷰 타입에 중첩된 레이아웃 타입과 갱신 경계를 줄인다. 카테고리, 이어보기,
  재생·상세 이동 및 접근성 레이블은 유지한다.
- 픽셀 테스트에서 빨강/파랑 이미지의 aspect-fill, 둥근 모서리의 낮은 알파,
  가운데 불투명도와 터치 비수신을 확인한다. 가장자리 안티앨리어싱은 허용한다.

단일 레이어로 바꿨다는 사실이 GPU offscreen pass 0회를 보장하지 않는다.
기능 검증 후에도 수정 전후 app update/render 비용 및 초기 hitch의 실기기 비교가 필요하다.

최대 글자 크기 감사 중 상단 로그아웃 텍스트의 Dynamic Type 지원 문제가 발견되어,
접근성 이름을 유지한 44pt 아이콘 버튼으로 보완했다. 감사 항목을 제외하거나 오류를
무시하지 않는다. 포스터 테스트는 실제 카드 스크린샷을 보존하며, 이미지/둥근 모서리/
제목 배치를 확인한다.

접근성 테스트의 상세 화면 스크롤 제한도 12회에서 24회로 보완했다. 최대 글자에서
에피소드 설명 뒤의 검사 버튼이 약 5,600pt 아래에 있어, 기존 제한에서는 계속 정상
스크롤되는 중에도 검사 위치에 도달하지 못했다. 화면 전체 노출·터치 가능 조건과
Dynamic Type/textClipped/hitRegion 감사 항목은 그대로 유지한다.

이번 후속 검증(2026-10-27): 픽셀/캐시 3개 통과. 홈 데모 재생, 포스터/검색 썸네일
상세 진입, 알림 최초 진입·로그아웃, 최대 글자 접근성 감사까지 관련 UI 4개 통과.
접근성 실패 원인 보완 후 전체 감사 재실행 성공. 최종 기기용 Release 빌드 성공.
포스터 실화면 캡처에서 그림, 둥근 모서리, 제목 배치를 확인했다.
실기기 수정 후 성능 수치/끊김 제거 완료는 아직 검증하지 않았다.

## 두 변경을 독립적으로 측정하기 위한 구성

현재 버전에 C/P/V/PV 비교 Scheme을 추가했다. 포스터 렌더링과 홈 뷰 분리를
독립적으로 선택하며 계정·데이터 로딩·접근성 수정 등 나머지 조건은 같다.
기존 A/B의 스크롤 동작·열 상태 차이로는 원인을 확정할 수 없어 마련한 측정 구성이다.
자세한 순서와 파일명은 [HOME_RENDER_EXPERIMENT.md](HOME_RENDER_EXPERIMENT.md)를 따른다.
성능 개선을 추가로 완료했다는 의미는 아니다.

## 공통 초기 준비 단계 계측

포스터/홈 뷰 분리 독립 비교만으로 초기 지연의 원인을 확정하지 못해,
`StreamLab-Startup` Release Scheme에 선택형 signpost 계측을 추가했다.
계정 복원, 프로필/세션/로컬 상태 준비, 홈 요청·발행·body 계산, 첫 hero layout
관찰 지점과 이미지 로드·디코딩을 같은 Instruments 시간축에서 비교한다.
[HOME_STARTUP_TRACE.md](HOME_STARTUP_TRACE.md)에 구간 의미와 첫 실기기 측정 방법을 정리했다.
이 계측을 실제 성능 개선 완료로 취급하지 않는다.
