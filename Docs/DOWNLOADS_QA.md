# 오프라인 다운로드 검증

상세 화면의 **HLS 샘플 다운로드**는 Apple 공개 테스트 영상을 받습니다.
기존 번들 MP4나 실제 작품 영상을 다운로드하는 기능으로 설명하지 않습니다.

## 자동 검사

```bash
caffeinate -i bash scripts/check-downloads-mac.sh
```

정책 11개와 실제 HLS 다운로드 → 고정 → 재실행 → 다운로드 보관함 → 프로필 분리 → 저장 파일 재생 → 삭제를 확인합니다.
최대 글자 크기에서 빈 보관함 안내에 접근할 수 있는지도 검사합니다.
외부 소스·Wi-Fi·시뮬레이터 지원 문제도 실패로 남깁니다. 실제 비행기 모드 증명은 아닙니다.
RESULTS.txt, environment.txt, core.log, ui-tests.log와 xcresult를 같은 실행 기준으로 보관합니다.

## 실제 iPhone

1. Wi-Fi 연결 후 상세 화면에서 다운로드. 진행 중에는 완료/재생으로 표시하면 안 됩니다.
2. 완료 후 앱 종료·재실행. 다운로드 탭에서 목록·고정 상태·저장 크기 유지 확인.
3. 비행기 모드를 켜고 Wi-Fi도 끈 뒤 다운로드한 샘플 재생. 탐색과 완료 확인.
4. 내려받지 않은 음성·자막을 온라인으로 가져오지 않는지 확인.
5. 다른 프로필로 전환하면 다운로드 탭과 작품 상세에 기존 프로필의 다운로드가 나타나면 안 됩니다.
6. 다운로드 두 개를 진행하고 세 번째 요청이 대기하는지 확인.
7. 공간 부족 시 고정한 파일/재생 중 파일은 유지하고 오래된 비고정 파일만 정리하는지 확인.
8. 진행 중 취소·앱 종료·재실행. 삭제가 끝나거나 재시도 오류를 표시해야 합니다.
9. 진행 중 로그아웃. 다시 로그인해도 이전 파일·기록이 노출되면 안 됩니다.
10. 홈 이동 후 완료 및 OS 백그라운드 재실행 확인. 강제 종료 시 OS 정책으로
    전송이 중단될 수 있으며, 다음 실행에서 실패/정리 상태로 복구해야 합니다.

앱 예산은 1GB, 작업당 보수적 예약은 500MB입니다. 시스템의 비동기 쓰기로 인해
순간적인 물리 디스크 사용량의 절대 상한은 보장하지 않습니다. 고정은 앱의 자동 정리에서
보호하는 기능이며 iOS 자체 저장 공간 정리를 막는 보장은 아닙니다.

## 2026-10-20 사용자 실기기 확인

컨테이너 경로 별칭 수정 후 다운로드 성공, 비행기 모드에서 앱 재실행 후 재생 및 앞뒤 탐색 성공을 사용자가 보고했습니다.
이는 사용자 확인 결과이며 자동 실행 로그로 측정한 결과는 아닙니다. 새 다운로드 보관함의 실기기 확인과 위 나머지 항목은 별도입니다.
메타데이터는 원자적으로 저장하는 JSON이며 SwiftData로 변경하지 않았습니다. 영상은 시스템이 관리하는 `.movpkg`에 저장합니다.

## 백그라운드·동시 전송·전송 중 로그아웃 전용 검사

```bash
caffeinate -i bash scripts/check-download-lifecycle-mac.sh
```

- 실제 외부 HLS로 다운로드를 시작하고 앱을 홈 화면으로 보낸다. 45초 뒤 복귀해
  OS 작업 종료와 오프라인 재생 가능한 패키지 저장을 검사한다.
- 서로 다른 작품 3개를 요청해 네이티브 작업 2개, 대기 1개와 기록 3개를 확인한다.
- 전송 중 로그아웃하고 다시 로그인해 OS 작업·계정 기록·JSON 기록·관찰한 패키지가
  모두 정리됐는지 확인한다. 재실행 후에도 작업/기록이 살아나면 실패다.
- DEBUG 전용 `--ui-test-download-lifecycle` 관찰 화면을 사용한다. 다운로드 시작은
  실제 저장소 enqueue를 호출하며 완료·취소·파일 삭제 결과를 주입하지 않는다.
  일반 실행 및 Release에는 검증 버튼이 없다.
- 시뮬레이터의 백그라운드/복귀 성공은 실기기 OS 종료 후 background-session wakeup
  증명이 아니다. 앱 강제 종료는 단순 홈 이동과 구분한다.

실기기에서 별도로 확인할 순서:

1. Wi-Fi에서 다운로드를 시작하고 진행 중에 홈 화면으로 이동한다. 앱을 강제 종료하지
   말고 1~2분 뒤 복귀해 저장 완료와 오프라인 재생을 확인한다.
2. 빈 보관함에서 서로 다른 작품 3개를 빠르게 요청한다. 두 개 진행·한 개 대기를
   확인한다. 완료가 너무 빠르면 관측하지 못한 것으로 기록하고 PASS로 처리하지 않는다.
3. 진행 중 로그아웃한 뒤 다시 로그인한다. 모든 프로필 보관함이 비어 있고,
   앱을 재실행한 뒤에도 이전 다운로드가 다시 나타나지 않는지 확인한다.

시스템 종료 후 앱 깨우기, 실제 디스크 부족, 전송 중 네트워크 변경은 별도 검증이다.

## 다운로드 진행률과 완료 알림

```bash
caffeinate -i bash scripts/check-download-notifications-mac.sh
```

- 보관함과 상세에 다운로드 중 퍼센트/막대, 대기·완료·실패·정리 중 상태를 표시한다.
  진행률이 끝에 도달해도 패키지 저장과 오프라인 재생 가능 여부를 검증하기 전에는
  100%/완료로 표시하지 않는다. 진행률은 네이티브 작업이 보고한 값이다.
- 다운로드 탭에서 **백그라운드 다운로드 완료 알림 켜기**를 누르면 시스템 권한을 요청한다.
  거절해도 다운로드는 가능하며, 이후에는 알림 설정으로 이동하는 버튼을 제공한다.
- 앱이 백그라운드일 때 성공적으로 저장된 파일만 로컬 알림을 예약한다. 서버 푸시가 아니다.
  작품명·계정명은 잠금 화면 알림에 넣지 않는다. 포그라운드 완료에는 알림을 예약하지 않는다.
- 취소/삭제/자동 정리는 해당 알림을 제거한다. 로그아웃은 첫 await 전에 알림을 차단하고
  대기/전달된 다운로드 알림을 제거한다. 권한 조회나 OS 예약 중 취소·로그아웃이 겹치면
  비동기 처리 후 다시 유효성을 검사해 늦은 예약도 제거한다.
- background-session 완료 핸들러는 알림 예약 작업이 끝난 뒤 반환한다.
- 실기기: 알림을 허용한 뒤 다운로드 중 홈 화면으로 이동해 완료 알림 확인 → 알림 센터에서
  확인 → 로그아웃 후 제거 확인. 별도 다운로드를 진행 중 취소하고 완료 알림이 오지 않는지 확인한다.
  집중 모드/알림 요약/기기 설정에 따라 배너·소리의 표시 시점은 달라질 수 있다.

사용자 실기기 추가 확인: 백그라운드 다운로드와 전송 중 로그아웃 검증 완료를 보고했다.
이는 이번 알림 기능 추가 전의 다운로드 동작 확인이며 새 완료 알림 표시 확인과 구분한다.

## 2026-10-21 — 실기기 사용자 확인 추가

사용자가 다운로드 완료 알림과 네트워크 재연결 배너 표시, 취소·로그아웃 시 알림이
오지 않는 것을 확인했다. 사용자 보고 범위의 실기기 검증이며 자동 로그/집중 모드의
모든 조합을 검증한 것으로 확대하지 않는다.

## 실패한 다운로드 다시 받기

```bash
caffeinate -i bash scripts/check-download-retry-mac.sh
```

- 실패 항목은 상세와 다운로드 탭에서 **다시 다운로드**를 누른다. 준비 중에는 버튼을
  비활성화해 중복 요청을 막는다. 수동 재시도이며 파일은 처음부터 새로 받는다.
- 현재 계정/프로필의 작품 접근 권한을 다시 확인하고, 남은 이전 패키지를 삭제한 뒤
  새로운 작업 번호로 교체해 저장한다. 새 기록 저장에 실패하면 전송하지 않는다.
- 기존 고정 설정은 유지한다. 이전 파일 삭제에 실패하면 기록을 유지하고 오류를 표시한다.
- 준비 중 프로필 전환/로그아웃/기록 삭제가 발생하면 이전 요청은 전송을 시작하지 않는다.
- 기존 동시 2개/용량 예약 정책을 그대로 적용한다. 실패 상태에서 자동으로 반복 재시도하지 않는다.
- 자동 UI 검사는 실제 네이티브 전송을 취소해 오류 콜백을 발생시킨다(실패 상태 자체를
  주입하지 않음). 재실행 후 재시도·새 작업 번호·중복 방지·완료·저장 파일 재생과,
  느린 권한 확인 중 프로필 전환 후 전송이 시작되지 않는 것을 확인한다.
- 실제 네트워크 단절의 오류 발생 시점은 iOS에 따라 다르며 이 검사에서 네트워크를 차단하지는 않는다.

## 2026-10-21 — 다운로드·플레이어 연결 끊김 배너

- 로그인 후 다운로드 탭을 포함한 앱 화면과 전체 화면 플레이어에서 오프라인 배너를 표시한다.
- 문구: “네트워크 연결이 없습니다. 저장된 콘텐츠는 이용할 수 있습니다.”
- 네트워크가 복구되면 기존 “네트워크에 다시 연결되었습니다.” 배너로 전환하고 5초 후 숨긴다.
- 배너는 연결 경로 상태 안내다. 실제 전송/재생 성공이나 서버 응답을 보장하지 않는다.
  배너 자체가 다운로드를 취소하거나 저장된 영상 재생을 중단하지 않는다.
- 자동 검증: `scripts/check-offline-banner-mac.sh`. 다운로드 화면과 전체 화면 플레이어의
  오프라인 표시→재연결 표시→자동 숨김을 검사한다. 경로 이벤트를 주입하고 플레이어는
  로컬 데모 소스를 사용하므로 실제 네트워크 차단·HLS 전송 장애 검증과 구분한다.
- 실기기: 다운로드 진행 중 Wi-Fi와 셀룰러를 모두 끄고 상단 안내를 확인한 뒤 다시 연결한다.
  온라인 영상 재생 중에도 반복한다. Wi-Fi만 껐을 때 셀룰러로 연결되면 오프라인이 아니다.
  저장된 영상은 연결이 없어도 계속 재생되어야 한다.
